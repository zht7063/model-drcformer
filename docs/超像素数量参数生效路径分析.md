### 6. 关键影响点总结

#### 6.1 超像素生成阶段
- **位置**：`datasets.py` 的 `get_spix_label` 函数
- **作用**：控制 SLIC 算法实际生成的超像素数量
- **影响**：如果指定 `num_sp_tokens=64`，SLIC 会尝试生成约 64 个超像素区域

#### 6.2 Token 化阶段
- **位置**：`models.py` 的 `tokenization` 方法
- **作用**：固定 token 序列的长度为 `num_sp_tokens`
- **影响**：
  - 如果实际超像素数量 < `num_sp_tokens`：部分 token 位置为空，通过 mask 屏蔽
  - 如果实际超像素数量 > `num_sp_tokens`：超像素标签会被裁剪到 `[0, num_sp_tokens-1]`，多个超像素可能映射到同一个 token

#### 6.3 注意力机制
- **位置**：`models.py` 的 `forward` 方法
- **作用**：注意力矩阵的维度由 `num_sp_tokens` 决定
- **影响**：类 token 对超像素 token 的注意力矩阵形状为 `(B, K, T)`，其中 `T = num_sp_tokens`

#### 6.4 CAM 生成
- **位置**：`models.py` 的 `forward` 方法（当 `return_att=True` 时）
- **作用**：CAM 映射时需要考虑有效的 token 数量
- **影响**：只使用有效的超像素 token（通过 `mask_tok` 筛选）

## 注意事项

1. **超像素数量 vs Token 数量**
   - `num_sp_tokens` 同时控制超像素生成数量和 token 序列长度
   - 如果实际生成的超像素数量与 `num_sp_tokens` 不一致，会有标签裁剪或空 token 的情况

2. **标签裁剪**
   - 在 `tokenization` 方法中，超像素标签会被裁剪到 `[0, num_sp_tokens-1]`
   - 这意味着如果实际超像素数量 > `num_sp_tokens`，多个超像素会映射到同一个 token

3. **Mask 机制**
   - 模型使用 mask 来屏蔽空的超像素簇
   - 这允许模型处理实际超像素数量 < `num_sp_tokens` 的情况

4. **性能影响**
   - `num_sp_tokens` 直接影响：
     - 注意力矩阵的大小：`(num_classes + num_sp_tokens) × (num_classes + num_sp_tokens)`
     - Token 序列长度：`num_classes + num_sp_tokens`
     - 内存占用和计算复杂度

## 常见问题

### 问题：训练时指定了 64 个超像素，但 CAM 中还是 196 个超像素的样子

**原因**：在 CAM 生成阶段，`generate_cam` 方法没有传递 `--num-sp-tokens` 参数给 `main.py`，导致使用了默认值 196。

**解决方案**：已在 `run_drcformer.py` 的 `generate_cam` 方法中添加了 `--num-sp-tokens` 参数传递，确保 CAM 生成时使用与训练时相同的超像素数量。

**修复位置**：
```214:223:src/drcformer/run_drcformer.py

            "python", "main.py",
            "--data-set", "VOC12MS",
            "--img-list", str(self.img_list_dir),

            "--attention-dir", str(cam_png_dir),
            "--cam-npy-dir", str(cam_npy_dir),
            "--resume", str(checkpoint),

            "--num-sp-tokens", str(self.num_sp_tokens),  # 确保 CAM 生成时使用与训练时相同的超像素数量
        ]
```

**验证方法**：重新运行 CAM 生成，检查生成的 CAM 图片中的超像素数量是否与训练时一致。
